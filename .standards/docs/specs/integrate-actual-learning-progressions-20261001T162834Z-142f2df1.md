# Technical Design

## Context

Feature architecture for the completed scope in
`.standards/docs/scope/integrate-actual-learning-progressions-20261001T162834Z-142f2df1.md`.
The active-cycle baseline is `.standards/CONTEXT.md`; there is no recovery frame.
The existing Python/FastMCP application is immutable, deterministic, read-only,
profile-driven, and local-data-only. Reuse its accepted-package lifecycle,
GraphStore, catalog routing, standard selectors/search, component links, resource
policy, prompt renderer, thin MCP adapters, and shared transport/distribution checks.

Six curricula supply 3,039 buildsTowards and 5,041 relatesTo edges. Their standards
and component delivery bytes match the current packages. The upstream combined
exports differ in format, so they cannot simply replace delivery JSONL. Stored LP
judgments are generated by IDinsight's producer/checker pipeline; structural
acceptance does not establish publisher endorsement or pedagogical correctness.

## Decision

Add LP relationships to each existing mixed Academic Standards package, keeping
`academic_standards` as its primary graph type and declaring
`learning_progressions` alongside `learning_components`. Use one package-local
GraphStore and one accepted runtime, with labels separating hasChild, supports,
buildsTowards, and relatesTo. No database, graph merge, network dependency, LLM
invocation, sampling, or curriculum-specific Python branches are needed.

Introduce one ordinary LearningProgressionsService with five typed query methods.
Replace the hypothesis tool/prompt and their machinery completely. Add three
client-executed prompt workflows and extend existing teaching/study instructions.
Reuse the exact relationship resource; add per-relationship provenance and an LP
summary resource. Keep rich provenance outside GraphRelationship: the graph holds
edges; small validated projections support queries; resources expose the complete
retained judgment.

Two packaging changes are necessary:

- Build new immutable snapshots and profile versions. Old accepted packages are
  sealed envelopes: adding evidence changes their checksum identity. Prepare and
  validate replacements separately, then retire the old package/profile/prompt
  directories from the active checkout; their history remains in Git and the
  copy receipt records old identities. Do not edit old terminal manifests or
  retain a legacy decoder/configuration path. Each deployed checkout continues
  independently; deployment remains user-owned.
- Partition provenance for exact reads. CBSE's provenance map is 40,860,837 bytes,
  above the existing 32 MiB source-read limit. Keep the original map unchanged and
  create 64 deterministic partitions whose contents are checked against it.
  This is like putting copies of individual evidence pages in smaller folders:
  teachers can open one relationship's evidence without opening the whole binder.
  Resource limits and rights remain enforced, including for the original binder.

The user impact is new snapshot/profile identities and an expanded public surface;
standard/component IDs, source text, useful services, hierarchy, and LC supports
remain intact. Module names, helper factoring, test organization, and reversible
local implementation details are Developer choices within these contracts.

## Interfaces and Contracts

### Local copy, normalization and immutable packages

Developer's first action before implementation changes is to copy all six
CONTEXT-mapped `<doc-key>/kgs/` input sets into
`data/source_artifacts/learning_progressions/<doc-key>/kgs/`. This directory is an
operator preparation/evidence boundary, outside graph-package discovery and MCPB
staging. Do not copy credentials, unrelated request logs, or the external project's
entire results tree. Select these existing files explicitly:

- AS/LC delivery: as_lc_nodes.jsonl, as_lc_relationships.jsonl.
- Existing detailed evidence: as_standards_framework.json,
  as_standards_framework_items.jsonl, as_relationships_has_child.jsonl,
  as_entity_provenance.json, as_unresolved_items.json, as_kg_bundle.json,
  as_lc_kg_bundle.json, as_lc_validation_report.json, lc_entity_provenance.json,
  lc_generation_summary.json, lc_dedup_groups.json.
- LP evidence: as_lc_lp_kg_bundle.json, as_lc_lp_nodes.jsonl,
  as_lc_lp_relationships.jsonl, lp_relationships_builds_towards.jsonl,
  lp_relationships_relates_to.jsonl, lp_relationship_provenance.json,
  lp_validation_report.json, lp_unresolved_items.json,
  lp_generation_summary.json, lp_final_claims.json.

Save a copy receipt beside these inputs with source/document/framework mapping,
repository-relative destination, size and exact SHA-256 for every file, copy-time
verification, and old package/profile identities. Verify source hashes before and
after copying and destination hashes; treat drift/missing inputs as a reconciliation
issue before packaging. Retain the receipt with the implementation evidence. Raw
preparation copies may remain local; required runtime evidence below must be in
accepted packages and available in a fresh repository/distribution checkout.

Provide a reproducible local preparation/normalization command in the existing CLI
family. Consume only copied files. Preserve nodes and AS/LC relationship lines
byte-for-byte; append LP wire records sorted by `(relationship_type, identifier)`.
Use delivery filenames `as_lc_lp_nodes_<token>.jsonl` and
`as_lc_lp_relationships_<token>.jsonl`, extending the existing safe filename rule.
The output relationships artifact retains the AS/LC prefix exactly, with a newline
separator if required; record that separator in the normalization receipt.

Normalize split LP detailed records, not format-varying combined nodes. Set outer
identifier and property identifier to the stored relationship identifier; set label
and relationshipType to the stored type; resolve each exact source/target CASE UUID
to the existing standard's outer node ID and StandardsFrameworkItem label. Map
snake-case detailed property names to current camel-case string properties and
`case_identifier_uuid` to wire `caseIdentifierUUID`. Preserve author, provider,
license, attribution, description and endpoint values without substitution. Omit
null optional dates; encode existing non-null dates as source strings. Rich metadata
is retained in the original provenance/detailed inputs, not flattened into string
properties. Never regenerate UUIDs, reverse builds edges, create symmetric copies,
or normalize source identifiers. Reject unknown/missing required fields.

Reconcile normalized edge IDs/types/endpoints and metadata against both split files,
the combined export (using explicit envelope/flat parsing), and the provenance map.
No accepted edge comes from final claims, candidates, needs_review or no_relation.
Do not rerun the producer/checker pipeline. Preserve upstream hashes as upstream
hashes, distinct from actual retained artifact-byte hashes.

Use manifest version `1.1`, delivery schema `1.2`, source schema `1.0`, package
revision 1; retain existing primary package-ID and artifact-set snapshot algorithms.
Use the old source version token: new artifact-set hashes distinguish the replacement
without implying a new curriculum edition. New profile schema `1.1`, profile version
`2.0`, removes progressionHeuristics from model/validation/JSON. New prompt config
schema `1.1` and profile version `2.0` remove the hypothesis overlay and permit the
three new overlays; public prompt version advances from `1.2.0` to `1.3.0`.
Preserve source current status; active distribution contains one current replacement
per framework, avoiding ambiguous-current routing. Retire old directories only after
all six replacements pass acceptance in a separate preparation root.

Extend dedicated PackageArtifacts/builder fields with logical names
`learningProgressionBuildsTowards`, `learningProgressionRelatesTo`,
`learningProgressionProvenance`, `learningProgressionValidation`,
`learningProgressionUnresolved`, `learningProgressionSummary`,
`learningProgressionFinalClaims`, `learningProgressionProvenanceIndex`, and
`learningProgressionNormalization`. These respectively retain the split LP files,
original map/report/unresolved/summary/final claims and generated index/receipt.
Reuse existing AS/LC detailed logical names. Combined LP bundles are copy-time
reconciliation inputs, not required duplicate bulk artifacts in the distribution.
All declared runtime artifacts participate in exact checksums and closed-tree checks.

The partition algorithm is `SHA256(UTF8(relationship_id))[0] modulo 64`. Write all 64
JSON maps with original entries unaltered, sorted keys, canonical UTF-8 JSON and one
final newline; additional-artifact logical names are
`learningProgressionProvenanceShard00` through `learningProgressionProvenanceShard63`.
Index format version `1.0` records this algorithm, original provenance logical name
and byte hash, and the exact manifest logical-name mapping. No caller supplies a
path, partition number or filename. Acceptance checks the index, unique exhaustive
partition union, deterministic placement and deep equality with the original map;
there must be exactly one entry for each accepted LP ID and no extras.

PackageCounts adds strict nonnegative `buildsTowardsRelationships` and
`relatesToRelationships`, zero when LP is not declared. Total relationships is all
four labels, while existing supports/hierarchy/unresolved counts keep their original
meaning. Compare the retained AS/LC validation report to the AS/LC subgraph, not the
new total; compare the retained LP report to LP counts. FrameworkCapabilities adds
`hasLearningProgressions` and `hasLearningProgressionProvenance`, derived from
accepted declarations/evidence, not merely a nonzero count or a global enum. A valid
zero-edge LP package is available with empty results; an undeclared LP capability is
unavailable. Generic non-LP synthetic packages remain supported by the new schemas.

LP acceptance validates outer/property ID and label/type agreement, standard-only
endpoints and exact CASE correspondence, no self edges, no duplicate IDs or typed
edges, canonical lexicographic CASE endpoint order for relatesTo, and pair exclusivity
across accepted LP types/directions. Validate generated attribution/provider/author
against retained LP evidence and source-framework identity/license independently
from hasChild authorship inheritance. Do not apply the supports generator rule to LP.
Required provenance structure contains claim candidate/judgment/trace, endpoint UUIDs,
relationship identity key, source framework and available input/config hashes;
judgment type/direction/endpoints must agree with the exported edge, confidence must
be finite in [0,1], and warnings/rationale retain their exact values. Validate retained
report structure, passed/errors/count agreement and unresolved/needs-review exclusion.
Missing mandatory evidence is an acceptance error, not a fabricated fallback.

Run directed cycle detection on buildsTowards separately from hasChild, never on
relatesTo; report distinct findings with offending IDs. Retain upstream warnings,
structural-only validation notices and eligibility limits as warnings/metadata.
Upstream reports are evidence, not a substitute for these server acceptance checks.
Use existing pending-to-terminal atomic acceptance and read-only revalidation;
invalid packages never become queryable. No resource-size limit is an excuse to skip
package integrity validation of large declared evidence.

### Query tools and shared results

Register these five new tools; all retain the existing read-only annotations,
FrozenSchema camel-case result aliases, thin adapters, and error boundaries:

| Tool                           | Required selection and operation                                                                                                                                                                                                                                                                                             |
|--------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| get_learning_progression       | framework_id, optional snapshot_id, exact relationship_id; require an LP edge and return its stored type/direction, both standard summaries, judgment projection and evidence links.                                                                                                                                         |
| get_standard_progressions      | same route, existing StandardIdentifier, connection_kind=`all` (default), `incoming_builds`, `outgoing_builds`, or `related`; paged direct links. Each entry names its meaning relative to the selected standard; relates combines both adjacency directions and deduplicates by ID, retaining canonical stored orientation. |
| search_learning_progressions   | same route; optional relationship_types, standard_identifiers, local_grade_labels, normalized_grades, statement_types, normalized_statement_types; endpoint_scope=`either` (default), `both`, `source`, `target`; paged discovery.                                                                                           |
| traverse_learning_progressions | same route and StandardIdentifier; direction=`upstream` or `downstream`, default downstream; bounded builds-only reachable subgraph with depth and exact edge references.                                                                                                                                                    |
| get_learning_progression_paths | same route, source_identifier and target_identifier using StandardIdentifier; bounded directed simple paths from source to target using builds only; endpoints must differ.                                                                                                                                                  |

Require framework_id for the LP surface. An omitted snapshot uses existing
unique-current resolution once, then pins the result to that exact snapshot.
A mismatched explicit framework/snapshot is rejected; no federated graph-type
selector or cross-package traversal is accepted. Reuse existing selectors for
node ID, CASE UUID, CASE URI and profile-enabled statement code. Unknown standard
and ambiguous identifier retain existing typed failures; do not guess.

Discovery's type array is empty for both types, otherwise only buildsTowards and
relatesTo are valid. Filter arrays have at most 32 unique nonblank values using
existing normalized token/profile facet rules. Validate supported local grades,
normalized facets and statement-type values against the selected profile; invalid
values are invalid requests rather than empty results. Optional standard_identifiers contains at most 20 unique selectors, each resolved
by the same exact standard lookup; it restricts matching endpoints to that set.
Return the resolved set and reject unresolved/ambiguous entries rather than silently
skipping them. Multiple values within a field are OR; different fields are AND on one endpoint. `either` means at least one
endpoint satisfies the whole filter conjunction; `both` means each does; source
and target mean stored orientation. Return endpoint_scope and per-endpoint matched
facets. No cross-endpoint mixing of grade and statement-type criteria. Normalized
grades stay retrieval facets, and relates source/target filters refer to its stored
canonical order, not an instructional direction. Missing endpoint grade information
is handled by the established standard facet machinery, including structural grade
context where it already applies; never infer a grade from an LP edge.

Every result carries resolved PackageReference plus profile hash/version, manifest
byte hash, source artifact hashes, request/limits, generated-origin and semantic
notices, and LP summary/validation/unresolved links. Edges keep exact IDs, author,
provider, attribution/license, endpoint node/CASE IDs, edge/provenance/standard URIs,
and epistemicStatus=`llm_inferred`. Paths/subgraphs have
`deterministic_derived` status with every hop referencing those generated edges.
They do not change an edge's epistemic origin.

Use deduplicated node/relationship tables for collections and paths. A standard
summary contains exact identifiers, code/type/grade facets and an explicitly marked
statement excerpt of at most 2,048 characters with its full standard URI. Judgment
projection carries confidence and its model-judgment disclaimer, rationale excerpt
at most 512 characters, total warning count, up to five warning excerpts of 512
characters each, and explicit omitted/excerpt flags plus full provenance URI.
Author/provider/license/attribution are retained, not rewritten as source-authored.
Never present excerpts as full evidence. Full candidate references and producer/
checker trace remain in the per-edge resource. Cache only validated small projections
in the accepted immutable runtime, releasing rich maps after acceptance; do not
read the 40 MB original on each query or create a second mutable graph store.

### Bounds, deterministic continuation and failure behavior

| Operation/budget                                     | Default | Hard maximum |
|------------------------------------------------------|---------|--------------|
| direct/discovery page limit                          | 25      | 100 edges    |
| page examined relationships                          | 5,000   | 5,000        |
| traversal depth                                      | 8       | 12           |
| traversal unique returned nodes                      | 100     | 250          |
| traversal returned edges                             | 100     | 100          |
| paths depth                                          | 6       | 12           |
| paths returned                                       | 3       | 20           |
| traversal/path examined adjacency edges              | 5,000   | 5,000        |
| path queue states                                    | 5,000   | 5,000        |
| encoded LP tool result, text plus structured content | 1 MiB   | 1 MiB        |

Caller-selectable limits are positive integers within these bounds and enforced in
service models as well as MCP schema. Queue/work/byte ceilings are server constants;
report them. A finite output limit alone is insufficient. Tool text is a concise
summary/link list, not a second copy of full tables. If one exact result or one entry
cannot fit, return `progression_result_too_large` with a resource-access recovery
hint; do not produce a zero-progress continuation loop or silently drop that entry.

Direct/discovery ordering is `(relationship type, relationship ID)` independent of
file order. A cursor is opaque bounded base64url (at most 4,096 characters), contains
format version, exact package/manifest/profile identity, normalized selection/filter
fingerprint, and the next candidate position. Bind page limit and other semantic
bounds to that fingerprint. Validate shape, identity, fingerprint, range and checksum
before use, using the existing cursor conventions; no process-local session state.
Advance through examined nonmatches as well as emitted matches. Stop before an entry
that would exceed page/byte budget and resume there. Return nextCursor while candidates
remain, even when a work-limited page has zero matches; reject stale/mismatched cursors
as `invalid_cursor`. Report examined/returned counts, page/byte/work stopping reason
and isComplete for the entire requested selection. A page is not the entire result
when nextCursor is present; total matching counts are exact only when actually fully
computed, otherwise null/explicit lower bounds. Package totals are separate metadata.

Traversal is breadth-first, neighbors sorted by relationship ID. Deduplicate nodes
and edges but retain branching/merging edges between already visited nodes. Preserve
stored edge orientation even upstream. Stop on depth/node/edge/work/byte bounds;
return distances, frontier/truncation reasons and counters. Connecting paths use
breadth-first partial paths with per-path visited IDs, no global visited-node pruning
that would suppress alternative paths. Order by hop count then relationship-ID tuple;
do not expand a completed target path. Bound queue insertion and examined edges before
allocation/work, as well as returned paths/bytes. Synthetic cycles cannot loop.
No enumeration of unlimited paths or automatic retries to bypass a bound.

Traversal/path responses distinguish completeness within requested depth from
exhaustion of the full reachable graph: `scopeComplete`, `graphExhausted`, and
`truncationReasons` (depth, node, edge, path, work, queue, byte bounds as applicable).
Depth-frontier checks count against work budgets. No continuation is offered for
traversal/paths; state that callers can change bounded inputs and rerun. Zero paths
with unexplored frontier/work is incomplete search. Even exhausted absence means no
stored connection, not no pedagogical connection. No direct edge is synthesized
from a multi-hop path.

Reuse framework_not_found, ambiguous_framework, standard_not_found,
ambiguous_graph_node, capability_unavailable, invalid_cursor and resource policy
errors. Add `learning_progression_not_found`, `invalid_progression_request` and
`progression_result_too_large` domain failures. A found non-LP relationship ID fails
LP exact lookup, while the generic relationship resource still works. Transport
validation rejects malformed types/enums/bounds through the established MCP mechanism;
service-level semantic invalid requests have stable typed codes. Complete valid empty
collections return successful empty results. Unexpected faults remain masked with
existing internal_error messages. No private paths/content leak through error details.

### Resources, rights and coverage

Keep `.../relationship/{relationship_id}` for exact stored LP content. Add:

- `kgfegmcp://framework/{framework_id}/snapshot/{snapshot_id}/relationship/{relationship_id}/provenance`
  for full LP provenance. Resolve only an accepted LP ID to its validated partition;
  return its complete original entry with origin/semantics notices. Hash returned
  canonical content and list original map, selected partition, index, relationships
  and manifest identities/hashes. Missing provenance never falls back to a model.
- `kgfegmcp://framework/{framework_id}/snapshot/{snapshot_id}/learning-progressions`
  for summary metadata: availability, per-type stored counts, structural-validation
  scope, candidate/claim/needs-review/unresolved counts actually present in retained
  report/summary, eligibility/coverage notices and artifact links. Missing coverage
  denominators remain unknown; zero incident counts do not erase edge warnings.

Use existing generic artifact URI for LP validation, unresolved, summary, final
claims, original split relationships/provenance, index and normalization receipt.
Explicit policies: validation, the derived sanitized LP summary resource, index
and normalization are public metadata; unresolved evidence is FULL_TEXT; original
generation summary, final claims, split edges, original map and declared partition
maps are BULK_CONTENT. Keep the original generation summary unchanged; its public
summary is a projection with its own content hash and original artifact-byte hash. Summary public metadata must exclude
rationale, candidate text, private filesystem paths and model prompts. Index and
normalization receipts exposed in a package use relative paths/logical names and
hashes, not the external absolute source path retained in the local copy receipt.
Partition generic exposure requires membership in the validated index and manifest,
not a permissive arbitrary-name prefix rule. Unknown additional artifacts fail closed.

Per-edge provenance has reviewed/full-text/single-standard rights checks, like
standard/component provenance, and does not grant bulk access. Both original and
partition hashes may be returned without reading the whole original resource; every
artifact actually read obeys max_resource_source_bytes, and final content obeys
max_resource_bytes. Keep defaults 32 MiB source and 8 MiB returned. Denied/oversized
raw evidence is explicit; do not inflate global limits. Lower operator-configured
limits still apply to partitions. Query summaries use the same reviewed/full-text/
standard policy before exposing endpoint text/judgment content; metadata counts stay
available under metadata policy. Prompt generation retains derivative policy checks.

Keep CBSE needs_review in inspectable unresolved evidence, not accepted edge tables.
Retain Ghana warning-pair evidence, per-edge warnings, source truncation/audit notices,
producer/checker hashes and generated attribution. Confidence is not a calibrated
likelihood of learner success. Candidate coverage is selected, not exhaustive; a
passed report says structural/process integrity only. buildsTowards supports success
without mandatory prerequisites; relatesTo is conceptual/skill relatedness without
sequence or dependency. Resource presence, provider approval or persistence does not
certify pedagogy or source-publisher endorsement.

does not execute an LLM or invent edges. The client executes the listed retrieval

## Data and Control Flow

1. Copy/verify external artifacts locally first; retain the exact-byte receipt.
2. Local normalization reuses AS/LC delivery, resolves LP endpoints, reconciles all
   exported edges and creates provenance partitions/index plus a sanitized receipt.
3. Builder hashes declared inputs and new profile bytes, derives new immutable
   snapshot identities and creates pending packages in a separate preparation root.
4. Validator independently checks records, original/partition evidence, counts and
   separate hierarchy/builds cycle constraints, then persists terminal acceptance.
   Once all six pass, active roots/configuration switch to new packages; old sealed
   artifacts are retired rather than overwritten. Runtime never performs this step.
5. Read-only bootstrap revalidates active packages, builds one graph/runtime per
   package, validated query projections, and shared services. Invalid data follows
   existing fail/quarantine rules and cannot masquerade as accepted evidence.
6. A tool pins a route, checks capability/rights, resolves selectors, executes its
   bounded label-specific operation, and returns exact identity/tables/links and
   completeness. A resource resolves declared safe paths, enforces rights/byte
   limits and returns content plus original/derived hashes.
7. A prompt pins the same route and renders a workflow. Client retrieval supplies
   stored evidence; client composition produces labeled pedagogy, never server edges.
8. Shared smoke and MCPB staging exercise the same accepted contracts through local
   transports and the retained distribution boundary. User handles later deployment.

## Risks and Follow-up

- Producer/checker judgments may be wrong or incomplete. Keep generated origin,
  rationale, warnings and structural-only scope visible; this feature does not
  certify or repair the upstream pipeline.
- Preparing new immutable packages temporarily needs disk for original and new
  evidence. Keep only required active runtime artifacts in MCPB; avoid loading
  duplicate full provenance maps after acceptance. No extra database is warranted.
- Source bytes may drift between audit and copy. Reconcile before dependence; a
  material change of source/eligibility needing new scope/context follows workflow
  failure routing rather than quietly weakening acceptance.
- A future much larger partition or lower operator byte limit can deny a resource;
  expose the failure and its verified identity. Raising global limits or adding an
  alternative storage engine is not needed for the audited six datasets.
- New snapshot/profile IDs and removed public hypothesis names intentionally change
  caller contracts. Preserve exact source IDs and explain these local package changes
  in later documentation; deployment timing is the user's decision.

## Alternatives

- Directly substitute combined AS/LC/LP exports: rejected because five curricula
  use incompatible flat records and replacement could disturb AS/LC delivery bytes.
- Separate LP graph packages/runtime or global graph database: rejected because
  endpoints already live in each package; duplicate routing/joins would complicate
  provenance, isolation and AS/LC synergy without solving a scoped need.
- Full provenance-map reads or higher global resource limits: rejected because CBSE
  already exceeds the source limit and most reads need one edge. Verified partitions
  reuse the existing safe artifact/resource boundary and keep rich evidence intact.
- Keep hypothesis aliases/heuristics or infer missing links: rejected by the explicit
  replacement scope and would confuse stored judgments with new client speculation.
